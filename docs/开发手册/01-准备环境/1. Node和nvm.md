## <span id="sec1">什么是 Node.js？为什么要使用它？</span>

【[返回标题](#title)】【[下一节](#sec2)】

**Node.js是一个免费、开源、跨平台的 JavaScript 运行时环境（Runtime Environment）**，它让 JS 不再局限于浏览器，可以用来创建服务器、Web 应用、命令行工具和脚本。本质上它就是一个让 JS 代码得以执行的「容器」或「平台」。

使用原因可以归为三个点：**用一门语言做更多事情**、**高性能的底层引擎**，以及**能做到高并发的架构**。

具体表现如下：

1. **让JS走出浏览器，而且不用另外新学一门编程语言**

   Node.js 内部集成了 Chrome 的 V8 引擎，也就是 Chrome 浏览器用来解析和执行 JavaScript 的那套引擎。V8 独立于浏览器存在，这一特性直接促成了 Node.js 的诞生。这意味着，原本只在前端页面里运行的 JavaScript，现在可以直接在操作系统上跑起来。对于已经熟悉 JavaScript 的开发者，这是最大的吸引力：**前端和后端可以使用同一种语言**，不必为了写服务端再去学 Java、Python 或 PHP。

2. **「事件驱动+非阻塞IO（Input/Output，输入/输出）」能让它处理大量同时发生的请求**

   Node.js 采用**事件驱动**和**非阻塞IO**模型。直白地说，就是当一个操作（读写文件、查询数据库等等）需要等待对方的结果时，Node.js 会腾出手来处理其他事情，不会让整个程序卡住干等着，等结果好了再回来继续。它的设计目标就是**让进程不被阻塞**，能用相对较小的资源开销同时应对许多连接。这使得它在同时服务大量的客户端，且每个请求的计算量都不大的时候显得非常高效。

3. **「主场」和「短板」明确**

   它的强项集中在「**密集IO+高并发+实时性强**」的场景，比如实时应用（聊天、协同编辑、行情推送）、高并发 API 与微服务、前后端同语言的 Web 后端，以及流处理与代理层。它的短板则是「**CPU密集计算**」，比如复杂的同步图像处理、重型数学计算等任务会阻塞事件循环，这类工作更适合交给 Python、Go 等语言或独立服务。



## <span id="sec2">如何安装 Node.js？</span>

【[返回标题](#title)】【[下一节](#sec3)】【[上一节](#sec1)】

打开 [Node.js 官方下载页面](https://nodejs.org/zh-cn/download) ，官方给的就是「使用nvm安装Node.js」的指引（**Windows除外**），命令官方已经贴出，照做就好。至于「什么是 nvm」，详见下节内容。

如果不想浪费时间打开链接，或者你的系统是Windows，笔者这里直接提供对应命令（最新日期**截至2026年10月27日**），请接着看下面的内容。

### Windows

由于官方`nvm`并不支持Windows，这里需要改为使用`nvm-windows`，这是一个社区维护的版本。

> ⚠️注意：虽然两者在使用上的作用相同，但它们的开发理念**完全不同**，也**不是**同一个团队开发。两者是**互相独立**的。有兴趣的同学可以自行搜索原因。

点击[此处](https://nvm-windows.com)前往官网，下载并安装`nvm-windows`。安装完成后打开一个**新的**命令提示符（cmd）或终端（PowerShell）。输入以下命令确认nvm可用：

```powershell
nvm version
```

然后再用它安装 Node.js。你也可以把下方命令中的`lts`替换成你要的版本。

```powershell
nvm install lts	# 安装最新的 Long-Term Support 长期支持版
nvm use lts	# 切换到这个 Node.js 版本
node -v	# 查看 Node.js 版本，有版本号就是成功
npm -v	# 查看 npm 版本，有版本号就是成功
```



### macOS / Linux

两者底层相似（Unix系统），因此可以共用以下命令：

```bash
# 下载并安装 nvm：
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash

# 代替重启 shell
\. "$HOME/.nvm/nvm.sh"

# 下载并安装 Node.js
nvm install 24

# 验证 Node.js 版本
node -v

# 验证 npm 版本
npm -v
```

该命令指引来自官网，同样可以把上面的`24`替换成你要的版本。



## <span id="sec3">什么是 nvm？为什么要使用它？</span>

【[返回标题](#title)】【[上一节](#sec2)】

nvm 的全称是 **Node Version Manager**，中文叫作「**Node.js 版本管理器**」。它是个管理工具，把每个 Node.js 版本安装在各自独立的目录里，用一条命令随时切换，互不干扰。

在上一章节，你实际上并没有「直接安装 Node.js」，而是先装了 nvm，再让 nvm 去安装和管理 Node.js。官网页面上直接展示 nvm 安装指令（Windows除外），本身就说明了它的默认地位：在官网看来，**用版本管理器来安装 Node.js 已经是推荐的操作方式**，而不是需要自己去别处发掘的「进阶选项」。



而DeepSeek对于「**为什么要用nvm**」的回答是这样的：

1. **Node.js 版本迭代很快，不同项目对版本的要求经常不一样**

   假设你本机全局是 Node 24，拉下来一个老项目却锁死在 Node 18，某个原生依赖在新版本下根本编译不过。直接安装的方式只能「装新覆盖旧」，想在新老项目之间切换，就得反复卸载、重装，而且每次重装都可能把全局安装的 npm 包一起弄丢。nvm 的做法是把每个版本装进各自独立的目录，切换时只改变当前环境指向哪个目录，已有版本原封不动地保留着。这样你可以在 Node 18 的项目里执行 `nvm use 18`，切到 Node 24 的项目再执行 `nvm use 24`，两边互不干扰，也不需要卸载任何东西。

2. **版本冲突之外，直接安装还会带来权限上的麻烦**

   当 Node.js 被装进系统目录时，全局安装 npm 包经常报权限错误，逼着你用 `sudo`。而一旦用 `sudo` 跑过 npm，缓存目录的权限就可能被搞乱，后续反而更麻烦。nvm 把 Node.js 装在用户自己的目录下，全程不需要 `sudo`，环境是用户态的、随时可切换的。它还把版本约定变成了可协作的东西：项目里放一个 `.nvmrc` 文件，进入目录执行 `nvm use`，就能自动切到约定的版本，减少「我本地能跑，你那里报错」的情况。这些好处叠加起来，才是官网把它放在安装页首屏的原因——它解决的不是一个孤立的「多版本」需求，而是安装、切换、权限和团队一致性这一整条链路上的问题。
