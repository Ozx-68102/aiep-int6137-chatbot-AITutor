# 编辑一轮的提问：以后要做的事

这次只写记录，不做实现。代码里在消息渲染的地方留了 TODO。

## 界面上是什么样

维护者给的原话：

- 每轮对话的下方有一个小的「编辑」按钮。
- 点击后展开一个修改框，用户可以在框里编辑里面的内容。
- 框里右下角有「取消」和「发送」两个按钮。
- 也可以点击之后直接按发送（在**用户视角**下，效果等同于「重试」）。

## 为什么想做

现在能改一轮的办法只有「重试」：原样再问一遍。问错了、字打偏了、想换个问法，
都只能把同一句再问一次。

顺带能解决一件事：**被按停止的那一轮，上游那边会留下一条只有提问的记录**
（我们自己那张 `message` 表里已经标出「对话已停止」，上游那份还没清）。
编辑重发的时候把旧记录删掉，那条悬空的提问也就没了。

## 服务器这边要做什么

跟「重试」是同一条路，只是内容换了：

1. 把这一轮在上下游的记录删掉（上游用 `core/chat/item/delete`，
   回答那条的编号是我们的轮次编号；我们自己那张 `message` 表里删这一轮的两行）。
2. 用改过的提问重新开一轮（新的轮次编号）。

「重试」现在带的是 `retryOf`（要重发的那一轮的编号）。编辑重发要再带一个字段：
新的提问内容。接口怎么加还没定（见下面的待定）。

## 待定的问题

- **「编辑」挂在哪儿**：维护者说的是「每轮对话的下方」，但改的是哪一条内容还没说死：
  用户提问那条，还是整轮（提问加回答）？按「重试」的逻辑看，应该是用户提问那条。
- **哪些轮次下面有**：每一轮都有，还是只有用户自己提的？
  被按停止的那一轮要不要给？（那一轮本来就没有「重试」按钮。）
- **改完以后原来那一轮的回答怎么办**：留在原地标成旧的，还是从历史里去掉？
  按「重试」现在的做法是去掉旧的（历史里始终一问一答）。
- **助手的回答能不能编辑**：编辑助手的回答再发一次没有意义。
  以后要是想做「换个模型再答一遍」，那是另一个入口。
- **框里按发送键是发送还是换行**：多行输入时按 Enter 通常是换行，
  是不是要用 Ctrl/Cmd+Enter 才发送。
- **三种语言都要有**：「编辑」「取消」「发送」（`src/i18n.ts`）。
