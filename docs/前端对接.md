# 前端对接说明

给负责聊天页面的人。后端在 `server/`，页面只通过 HTTP 访问，不要 import `server/` 里的代码。

`src/api/chat.ts` 现在仍返回本地示例句子。`vite.config.ts` 还没有把 `/api` 转到后端。这两处都还没接上。

## 本地怎么同时跑

先在 `server/` 准备一次数据库。仓库根目录再分别起接口和页面：

```bash
cd server
uv run python -m server.db.init
cd ..
pnpm run dev:backend
pnpm run dev:frontend
```

`dev:backend` 把接口拉到 `http://127.0.0.1:3001`。`dev:frontend` 只起页面。请在 `vite.config.ts` 把 `/api` 转到 `http://127.0.0.1:3001`，页面里的请求写相对路径 `/api/...`。

登录状态放在名为 `login` 的 cookie 里。页面脚本读不到它。登录后保留 7 天。之后每个带上这个有效 cookie 的请求，都会把有效期重新写成 7 天。连续 7 天没有任何请求，就要重新登录。关掉浏览器不会立刻丢掉。退出登录会马上删掉它。请求必须带上 cookie，例如 `fetch("/api/sessions", { credentials: "include" })`。在 Vite 把 `/api` 转到 3001 之后，浏览器会把它看成同一个站点，cookie 才会带上。

先只有一个账号：用户名 `admin`，密码 `admin`。别的用户名会得到 401。代码里有 TODO，以后会改成按账号表查找。

## 已经有的接口

字段名是蛇形，例如 `title_locale`、`created_at`。时间是 ISO 字符串。

### `POST /api/login`

请求体（以现有测试账户为例）：

```json
{ "username": "admin", "password": "admin" }
```

成功为 200，并写入 `login` cookie。响应体：

```json
{
  "locale": "zh-CN",
  "sessions": [
    {
      "id": "uuid",
      "title": null,
      "title_locale": null,
      "created_at": "2026-10-25T14:00:00Z"
    }
  ]
}
```

用户名或密码不对：401，`detail` 为「用户名或密码不正确」。没有 cookie 时不会出现这条。

### `POST /api/logout`

需要 cookie。没有请求体。成功为 204，没有正文，并删掉 `login` cookie。只退出这一次登录，同一账号在别的浏览器里的登录还在。未登录：401，`detail` 为「未登录」，cookie 也会被清掉。

### `GET /api/profile`

需要 cookie。给用户资料用。响应体：

```json
{ "id": "uuid", "username": "admin", "locale": "zh-CN" }
```

`locale` 只可能是 `zh-CN`、`zh-TW`、`en`。未登录：401，`detail` 为「未登录」。

### `PATCH /api/profile`

需要 cookie。请求体只有语言：

```json
{ "locale": "zh-TW" }
```

成功为 200，响应体和 `GET /api/profile` 相同，其中 `locale` 已是新值。语言不在那三个值里：请求会被拒绝。未登录：401。

### `GET /api/sessions`

需要 cookie。返回上面的 `sessions` 数组，按创建时间从早到晚。未登录：401，`detail` 为「未登录」。

### `POST /api/sessions`

需要 cookie。没有请求体。新建一条空会话：`title` 和 `title_locale` 都是 `null`。响应体是一条会话，不是整份列表。未登录同样是 401。

### `PATCH /api/sessions/{会话id}`

需要 cookie。会话必须属于当前账号。请求体：

```json
{ "title": "新标题" }
```

`title` 必填，1 到 500 个字符。成功为 200，响应体是更新后的那一条会话。原来的 `title_locale` 保持不变。未登录：401。会话不存在或不属于这个账号：404，`detail` 为「会话不存在」。

### `DELETE /api/sessions/{会话id}`

需要 cookie。会话必须属于当前账号。成功为 204，没有正文。先让 FastGPT 删掉这场会话；上游没有这场记录时，仍删除我们数据库里的会话，并清掉 Redis 里还没过期的半截文字。上游返回其他错误时，本地会话保留。未登录：401。会话不存在或不属于这个账号：404，`detail` 为「会话不存在」。

### `GET /api/sessions/{会话id}/partial`

需要 cookie。`会话id` 是创建会话时返回的 uuid，并且必须属于当前账号。用来在刷新后读 Redis 里还没过期的半截回答。

没有半截文字时：

```json
{ "status": null, "text": "" }
```

正在生成时 `status` 为 `streaming`。这一轮已经在上游存完、键还没过期时为 `finished`。`text` 是已经收到的文字。

未登录：401，`detail` 为「未登录」。会话不存在，或不属于这个账号：404，`detail` 为「会话不存在」。

### `GET /api/sessions/{会话id}/messages`

需要 cookie。打开旧会话时用它读取已经存在 FastGPT 里的消息。查询参数 `offset` 和 `page_size` 都必填。`offset` 从 0 开始，`page_size` 至少为 1。后端把它们原样转成上游的 `offset` 和 `pageSize`。

```json
{
  "total": 2,
  "messages": [
    { "id": "上游的 dataId", "role": "user", "text": "你好" },
    { "id": "上游的 dataId", "role": "assistant", "text": "你好" }
  ]
}
```

`total` 是上游给的总条数。`messages` 只保留 `obj` 为 `Human` 或 `AI`、并且能读到文字的记录，顺序与上游 `list` 一致。`Human` 对应 `user`，`AI` 对应 `assistant`。同一条记录里的多段文字按顺序接在一起。没有 `locale`，上游不提供。

未登录：401。会话不存在或不属于当前账号：404，`detail` 为「会话不存在」。缺查询参数，或 `offset` 小于 0，或 `page_size` 小于 1：请求会被拒绝。上游失败：500，`detail` 为「服务器错误」。

后端不会阻止连续新建多条空会话。页面上要自己处理：如果当前已经有一条完全空的会话（用户没输入，也没有任何输出，包括错误信息），再次点击「创建新会话」时静默忽略，不报错、不提示。直到这条会话里有了内容，才允许再创建。

## 发消息

FastGPT 的访问地址、密钥和应用 ID 已经在服务器的 `.env` 里。页面不要读这些值。

官方说明：[对话接口](https://doc.fastgpt.io/zh-CN/openapi/chat)。访问地址本身以 `/api` 结尾。代理会自己请求 `{访问地址}/v1/chat/completions`，请求头带密钥，正文带 `appId`。会话 id 当作 `chatId` 传过去。FastGPT 按这个 id 保存历史，页面每次只发本轮的文字。`chatId` 必须短于 250 个字符，前端现有的 UUID 符合。

工作流输入框里若没有 `[某名字]` 这种占位，请求不带 `variables`。

### `POST /api/chat`

需要 cookie。请求体：

```json
{ "message": "用户这一轮的话", "chatId": "会话 id", "locale": "zh-CN" }
```

`message` 和 `chatId` 必填。缺 `chatId`、缺 `message`，或 `chatId` 不是 uuid，请求会被拒绝。`chatId` 必须是当前账号的会话，否则 404，`detail` 为「会话不存在」。`locale` 可省略，后端不把它转给上游。

未登录：401，`detail` 为「未登录」。上游在吐出任何文字之前失败：500，`detail` 为「服务器错误」。已经开始输出后上游失败：连接结束，不再发送 `[DONE]`。

浏览器断开后，后端仍会把上游读完，并把半截文字写入 Redis。刷新后用上一节的 `partial` 接口接上。新的一轮开始时，这一场会话上一轮留在 Redis 里的文字会被清掉。

成功时响应类型是 `text/event-stream`。增量文字在 `choices[0].delta.content`。结束标记是单独一行 `data: [DONE]`。

```text
data: {"choices":[{"delta":{"content":"你"}}]}

data: {"choices":[{"delta":{"content":"好"}}]}

data: [DONE]
```

页面用 `fetch` 读取 `response.body`，把每块 `content` 追加到当前助手气泡。收到 `[DONE]` 或请求失败时结束加载状态。失败信息也算这条会话里已经有内容。
