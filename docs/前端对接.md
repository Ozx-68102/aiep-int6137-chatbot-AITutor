# 前端对接说明

给负责聊天页面的人。后端在 `server/`，页面只通过 HTTP 访问，不要 import `server/` 里的代码。

`src/api/chat.ts` 现在仍返回本地示例句子。`vite.config.ts` 还没有把 `/api` 转到后端。这两处都还没接上。

## 本地怎么同时跑

先在 `server/` 目录准备数据库并启动接口（只需准备一次数据库）：

```bash
cd server
uv run python -m server.init_db
uv run uvicorn server.app:app --host 127.0.0.1 --port 3001
```

仓库根目录仍用 `pnpm dev` 起页面。请在 `vite.config.ts` 把 `/api` 转到 `http://127.0.0.1:3001`，页面里的请求写相对路径 `/api/...`。

登录状态放在名为 `login` 的 cookie 里。脚本读不到它。请求必须带上 cookie，例如 `fetch("/api/sessions", { credentials: "include" })`。在 Vite 把 `/api` 转到 3001 之后，浏览器会把它看成同一个站点，cookie 才会带上。

先只有一个账号：用户名 `admin`，密码 `admin`。别的用户名会得到 401。代码里有 TODO，以后会改成按账号表查找。

## 已经有的接口

字段名是蛇形，例如 `title_locale`、`created_at`。时间是 ISO 字符串。

### `POST /api/login`

请求体（以现有测试账户为例）：

```json
{ "username": "admin", "password": "admin" }
```

成功为 200，并写入 `login` cookie。响应体：

```json
{
  "locale": "zh-CN",
  "sessions": [
    {
      "id": "uuid",
      "title": null,
      "title_locale": null,
      "created_at": "2026-10-25T14:00:00Z"
    }
  ]
}
```

用户名或密码不对：401，`detail` 为「用户名或密码不正确」。没有 cookie 时不会出现这条。

### `GET /api/sessions`

需要 cookie。返回上面的 `sessions` 数组，按创建时间从早到晚。未登录：401，`detail` 为「未登录」。

### `POST /api/sessions`

需要 cookie。没有请求体。新建一条空会话：`title` 和 `title_locale` 都是 `null`。响应体是一条会话，不是整份列表。未登录同样是 401。

后端不会阻止连续新建多条空会话。页面上要自己处理：如果当前已经有一条完全空的会话（用户没输入，也没有任何输出，包括错误信息），再次点击「创建新会话」时静默忽略，不报错、不提示。直到这条会话里有了内容，才允许再创建。

## 发消息

FastGPT 的访问地址、密钥和应用 ID 已经在服务器的 `.env` 里。页面不要读这些值。

官方说明：[对话接口](https://doc.fastgpt.io/zh-CN/openapi/chat)。代理会自己请求 `{访问地址}/api/v1/chat/completions`，请求头带密钥，正文带 `appId`。会话 id 当作 `chatId` 传过去。FastGPT 按这个 id 保存历史，页面每次只发本轮的文字。`chatId` 必须短于 250 个字符，前端现有的 UUID 符合。

工作流输入框里若没有 `[某名字]` 这种占位，请求不带 `variables`。

### `POST /api/chat`

这个路由还没有写进 `server/src/server/app.py`。现在调用会得到 404。约定先写在这里，避免页面和代理各猜一种格式。

需要 cookie。请求体：

```json
{ "message": "用户这一轮的话", "chatId": "会话 id", "locale": "zh-CN" }
```

`message` 和 `chatId` 必填。缺 `chatId` 应拒绝。`locale` 可省略。

成功时响应类型是 `text/event-stream`。增量文字在 `choices[0].delta.content`。结束标记是单独一行 `data: [DONE]`。

```text
data: {"choices":[{"delta":{"content":"你"}}]}

data: {"choices":[{"delta":{"content":"好"}}]}

data: [DONE]
```

页面用 `fetch` 读取 `response.body`，把每块 `content` 追加到当前助手气泡。收到 `[DONE]` 或请求失败时结束加载状态。失败信息也算这条会话里已经有内容。

## 还没有地址的功能

语言只能在登录结果里读到 `locale`。还没有修改语言的接口。页面上的语言切换仍只存在浏览器内存里，需要改成保存在 PostgreSQL 数据库中。

这些都还没有路由，不要先调用：

- 重命名会话
- 置顶会话
- 分享会话
- 删除会话

管理员后台页面也还没有。
