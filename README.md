# $H^2$ Bot

学生遇到讲不明白的问题时，在这里接着问。名字里的两个 H 是 Help 和 Higher Understanding：先把卡住的地方讲清楚，再帮人明白它为什么是这样，而不是只丢一个答案。

页面在仓库根目录，接口在 `server/`。浏览器只访问本仓库的接口。账号、会话和登录状态记在 PostgreSQL 里。回答由 `.env` 里配置的 FastGPT 应用生成，密钥不进页面。地址栏里记着当前是哪一场对话，刷新、后退键都会回到那一场。一轮回答如果中途断了，已经写出的半截文字会在 Redis 里留一段时间，刷新后可以接上。

## 页面上能做什么

用账号登录。登录状态放在 cookie 里，会保持一段时间；连续一段时间没有任何请求后需要重新登录。

登录后可以开对话、看以前的消息、接着问。助手还在想的时候，气泡里是三个跳动的点；答案到了以后整段淡入，不是一字一字地蹦。等答案的时候发送按钮会变成停止按钮，按下去这一轮就此打住，已经写出来的半截留着。刷新页面接得上：正在回答的那一轮，提问、三个点和已经写出来的半截都还在。界面语言可以在简体中文、繁体中文和英语之间切换，选择会记在账号上。

左侧是会话列表。新建的对话在发出第一条消息之后才出现在列表里；地址栏是空的（或者没有会话 id）时，页面停在新建对话的空白状态。每条会话可以重命名、删除或置顶。置顶时间由页面在置顶时交给接口保存，列表仍按创建时间从接口返回，页面再把较早置顶的放在上面。删除会话时，也会请 FastGPT 删掉对应的那场记录。

窄屏幕上，会话列表收成从旁边滑出的一层。连不上接口时，页面留在原地，提示稍后再试，而不是立刻回到登录页。

## 本地运行

工具版本和 Git 钩子见 [docs/TECH.md](docs/TECH.md)。实际用下来和文档对不上的地方记在 [docs/FINDINGS.md](docs/FINDINGS.md)。

先在本机装好 PostgreSQL 和 Redis，并确认它们已经在运行。再在仓库根目录准备 `.env`：复制 `.env.example`，填上自己的 FastGPT、数据库和 Redis 连接信息。

仓库根目录执行：

```bash
pnpm install
pnpm run dev:frontend
pnpm run dev:backend
```

两条命令各开一个终端。页面开发服务器起来后，浏览器访问它的地址。接口听 `127.0.0.1:3001`，页面把 `/api` 转到这里。

第一次准备表和初始账号时，在 `server/` 里执行：

```bash
uv run python -m server.db.init
```

这条命令只补还没有的表和列。账号已经存在时，不会改密码，也不会清掉已有会话。初始账号的用户名和密码写在 `server/src/server/db/init.py`。

Python 命令都在 `server/` 里用 `uv run`，不要在仓库根目录直接用 `python` 或 `pip`。
